Backend Progress Streaming Options

How should the backend communicate LangGraph progress to the frontend?

Option A: Server-Sent Events (SSE)

Backend pushes events via /api/workflows/{id}/events
POST /api/workflows → returns run_id
GET /api/workflows/{run_id}/events → SSE stream

Event: {type: "stage_start", stage: "generating_diagram"}
Event: {type: "llm_thinking", stage: "generating_diagram"}
Event: {type: "stage_complete", stage: "generating_diagram"}
Event: {type: "stage_start", stage: "generating_terraform"}
...

Pros

  • Simple, one-way communication
  • Built into FastAPI and browsers
  • Automatic reconnect support

Cons

  • One stream per workflow
  • No bidirectional communication

Option B: WebSocket

Bidirectional socket with persistent connection
ws://host/ws/workflows/{run_id}

Backend → Frontend: {stage: "generating_diagram", status: "in_progress"}
Backend → Frontend: {stage: "generating_diagram", status: "complete"}
Frontend → Backend: {action: "approve_diagram", run_id: "..."}

Pros

  • Bidirectional communication
  • Lower latency than SSE
  • Can send approve commands over same channel

Cons

  • More complex setup
  • Requires WebSocket support in reverse proxy
  • Need to manage connection lifecycle

Option C: Polling

Frontend polls /api/workflows/{id} every few seconds
Every 3 seconds:
GET /api/workflows/{run_id}
→ {stage: "generating_diagram", status: "in_progress", message: "Thinking..."}

Backend stores current state in DB, frontend checks periodically.

Pros

  • Simplest implementation
  • Works with any HTTP setup
  • Easier to debug

Cons

  • Latency up to poll interval (3s)
  • Wasteful if nothing changes

Which streaming approach do you prefer? My recommendation is SSE for simplicity with real-time updates.
