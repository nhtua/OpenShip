Implementation Approaches

How to integrate SSE streaming with the LangGraph workflow

Approach 1: Inline SSE with Synchronous Execution

Simple, but blocks during LLM processing
@router.get("/workflows/{id}/events")
async def stream_events(run_id: str):
    async def event_generator():
        yield event("stage_start", "generating_diagram")
        diagram = generate_diagram_llm(requirements)
        yield event("stage_complete", "generating_diagram")
        yield event("stage_start", "generating_terraform")
        terraform = generate_terraform_llm(...)
        yield event("stage_complete", "generating_terraform")
    return StreamingResponse(event_generator(), media_type="text/event-stream")

Pros

  • Simplest implementation
  • Direct control over event emission
  • No state management needed

Cons

  • Connection must be kept open entire time
  • If client disconnects, no way to resume
  • LLM calls block event emission

Approach 2: Async Task with Shared State + SSE

LangGraph runs as background task, events via shared state
# Backend: Start workflow as async task
async def run_workflow_background(run_id):
    graph = compile_langgraph_workflow(on_event=emit_event)
    result = graph.invoke({"requirements": req})
    store_result(run_id, result)

# SSE endpoint reads from shared event queue
@router.get("/workflows/{id}/events")
async def stream_events(run_id: str):
    async def event_generator():
        while True:
            event = await event_queue.get(run_id)
            if event.type == "complete":
                break
            yield event

Pros

  • Workflow can run independently
  • Client can reconnect and catch up
  • LLM processing doesn't block event loop
  • More resilient to connection issues

Cons

  • More complex (requires event queue)
  • Need to manage shared state
  • More moving parts to debug

Approach 3: LangGraph Checkpointing + SSE Callbacks

Use LangGraph's built-in checkpointing for state persistence
# Use LangGraph's checkpoint saver to persist state
checkpointer = SqliteSaver("checkpoints.db")
graph = StateGraph(WorkflowState)
graph.compile(checkpointer=checkpointer)

# Stream events from checkpoint transitions
@router.get("/workflows/{id}/events")
async def stream_events(run_id: str):
    async def event_generator():
        config = {"configurable": {"thread_id": run_id}}
        async for chunk in graph.astream(req, config=config):
            yield event("checkpoint", chunk)

Pros

  • Uses LangGraph's native streaming
  • State automatically persisted
  • Can resume from any checkpoint
  • Most robust long-term solution

Cons

  • Requires learning LangGraph's checkpointing API
  • More setup (checkpoint database)
  • Overkill for PoC stage

My recommendation: Approach 2 (Async Task + SSE) balances complexity with real-time updates and resilience. Approach 1 is simplest but less robust.
